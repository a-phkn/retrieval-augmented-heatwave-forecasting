# Architecture

disagrees with the code, the code wins and this file needs fixing.

│   └── forecast_windows.parquet
├── tests/

├── download_era5.py                 # Step 1a: pulls raw ERA5 via Open-Meteo, 9 grid cells, resumable
├── process_weather.py               # Step 1b: merges cells, area-average, feature engineering
├── prepare_datasets.py              # Step 2: climatology, episode labeling, split, leakage test generation
├── check_heatwaves.py               # ad-hoc sanity script (plots/checks known heatwave years)
├── requirements.txt                 # pandas, pyarrow, pytest, torch
├── training/
│   ├── __init__.py
│   ├── data.py                      # window builder + train-only normalization
│   ├── baselines.py                 # persistence + climatology sanity baselines
│   ├── train_lstm.py                # 5-seed LSTM training loop, weighted MSE loss (hot_weight=10), early stopping
│   └── evaluate_lstm.py             # extended val metrics: per-horizon MAE/RMSE, R², MAPE, heatwave-detection confusion matrix, bias diagnostic, baseline comparison (loads existing checkpoints, no retraining)
├── models/
│   ├── __init__.py
│   ├── lstm.py                      # LSTMForecaster: 2-layer LSTM(h=64) + MLP head
│   └── baseline_lstm/seed_{0..4}/checkpoint.pt   # canonical baseline, weighted-MSE trained (see context/decisions.md for why plain MSE was retired)
├── evaluation/
│   ├── normalization_stats.json     # train-only z-score stats (feature + target)
│   ├── sanity_baselines.json        # persistence/climatology metrics, all splits
│   └── baseline_lstm/
│       ├── val_metrics.json         # 5-seed val MAE/RMSE summary + per-seed history

Not yet present: `retrieval/`, `experiments/`, `visualization/`, `frontend/`
(all P3/P4, not started).

## Data flow (implemented so far)
```
download_era5.py
  → raw/*.json (gitignored, one per grid cell per chunk)
process_weather.py
  → data/processed/weather_daily.parquet
  → data/processing_log.json
prepare_datasets.py
  → events/event_catalogue.parquet
  → datasets/all_daily.parquet, {train,val,test}.parquet, forecast_windows.parquet
  → tests/test_no_leakage.py (generated)
```

## Data flow (P2, Step 3 — implemented and verified this session)
```
training/data.py
  → reads datasets/forecast_windows.parquet + datasets/all_daily.parquet
  → builds (X: (14,13), y: (5,)) arrays per split
  → fits/saves z-score normalization stats from TRAIN split only
  → evaluation/normalization_stats.json
training/baselines.py
  → persistence + climatology baselines, no training, direct metric computation
  → evaluation/sanity_baselines.json
models/lstm.py
  → LSTMForecaster: 2-layer LSTM (h=64, dropout 0.2) → MLP(64→32→5)
training/train_lstm.py
  → 5-seed training loop, weighted MSE loss (hot_weight=10), early stopping on val loss
  → models/baseline_lstm/seed_{n}/checkpoint.pt
  → evaluation/baseline_lstm/val_metrics.json
training/evaluate_lstm.py
  → loads the 5 checkpoints, no retraining
  → per-horizon MAE/RMSE, R², MAPE, heatwave-detection confusion matrix,
    bias diagnostic, persistence/climatology comparison on the same framing
  → evaluation/baseline_lstm/val_extended_metrics.json
```
Run with `python -m training.data` / `python -m training.baselines` /
`python -m training.train_lstm` from repo root (see `environment.md` for
why `-m` matters here).

## Key interfaces
- **Leakage boundary contract:** any code building retrieval candidates must
  respect `datasets/forecast_windows.parquet`'s
  `retrieval_candidate_latest_start` column and must independently satisfy
  `tests/test_no_leakage.py`. Do not hand-roll a different boundary
  calculation.
- **Split contract:** `all_daily.parquet['split']` and
  `forecast_windows.parquet['split']` are the only sources of truth for which
  split a date/window belongs to. Never re-derive from raw date comparisons
  scattered in downstream code — import the split boundaries from
  `config/data_spec.yaml` if a fresh computation is ever needed.
- **Normalization contract:** stats are fit on train split only, applied
  unchanged to val/test. Whoever trains a model owns fitting/saving these
  stats (not baked into the parquet files).

## State management
No persistent runtime state — checkpoints and metrics are the only artifacts
that carry state between runs, saved to `models/` and `evaluation/`.

## Known technical debt / rough edges
- `tests/test_no_leakage.py` is a generated file (from `prepare_datasets.py`).
  Editing it directly will be silently overwritten if `prepare_datasets.py`
  is re-run — extend it via `prepare_datasets.py`'s test-writing logic
  instead, if it ever needs more coverage (e.g. once P3 adds split-eligibility
  and same-episode exclusion, those need their own tests, added the same
  generated way or as a separate `test_retrieval_eligibility.py`).
- No `retrieval/`, `models/`, `training/`, `evaluation/` dirs exist yet in git
  history before this session — anything under them is new, unreviewed code.
